## 一 · 装到哪一层 —— **判据：这道门的知识是「通用」还是「项目特定」**

| 门 | 知识性质 | 装哪层 |
|---|---|---|
| ① `outward-guard` 对外动作要授权 | **通用** —— 任何项目都成立 | **用户级** |
| ② `bulk-write-guard` 批量改要先看清单 | **通用** | **用户级** |
| ③ `path-guard` 哪些目录算"内" | **项目特定** —— 每个项目不一样 | **项目级** |
| ④ `stop-guard` | —— 已实测否定，不装 | — |

**为什么 ③ 不能装用户级**：它的白名单只能填一个**宽**范围（否则误拦）。
填宽了 ⇒ **等于没拦** —— 而你会以为它在保护。

**实际装载**（用户级）：`~/.claude/hooks/{outward-guard.py, bulk-write-guard.py}`
+ `~/.claude/settings.json` 的 `PreToolUse` 新增一组 `matcher: "Bash"`。

> 新的这组是 `Bash` —— **匹配的工具集不相交，不互相干扰**。
> （规则：**逐字相同的 handler 跨 settings 文件去重、只跑一次；不完全相同的都跑。**）

## 二 · ⭐ 层级知识（**装之前必须知道，否则白装**）

**实际是 5 层，不是 3 层**（高 → 低）：

| # | 名字 | macOS 路径 | 范围 | 进 git |
|---|---|---|---|---|
| 1 | **Managed settings**（俗称"系统级"） | `/Library/Application Support/ClaudeCode/managed-settings.json` | **整台机器** | 管理员下发 |
| 2 | CLI 参数 | `claude --settings …` | 单次会话 | ❌ |
| 3 | **Project local** | `<项目>/.claude/settings.local.json` | 一个项目 | ❌ |
| 4 | **Shared project** | `<项目>/.claude/settings.json` | 一个项目 | ✅ |
| 5 | **User** | `~/.claude/settings.json` | **本机所有项目** | ❌ |

### 四个坑

| # | 坑 | 后果 |
|---|---|---|
| **①** | **`.claude/settings.json` 无父目录回退** —— 从子目录启动就不加载 | 门"装了但没生效" |
| **②** | ⚠️ **但 `.claude/settings.local.json` 相反**，它**从 git 仓库根读** | 两个文件行为相反，**别记混** |
| **③** | ⚠️ **`CLAUDE.md` 向上遍历，`settings.json` 不遍历** | 同项目里，前者找得到、后者找不到 |
| **④** | 🔴 **项目级 hooks 在「信任这个文件夹」之前就会跑** | **一个你还没信任过的仓库，它的 hook 已经在你机器上以你的身份跑** |

**还有一条**：**`deny` 跨层永远赢** —— `user` 层的 deny 能压住 `project` 层的 allow（评估顺序 deny → ask → allow）。

### 由此得出一条本仓的设计决定

> **本仓的设置文件叫 `settings.project.json` / `settings.user.json`，故意不叫 `.claude/settings.json`。**

**因为本仓是公开仓** —— 若仓里躺着 `.claude/settings.json`，
**任何人 clone 下来、在没点信任之前，它的 hook 就已经跑了**（见上表坑④）。
那等于**给陌生人装后门**。

**代价**：装的时候必须有人为的"复制过去"这一步 —— 这正是 `harness/README.md`
「**复制文件 ≠ 装上了**」那一条的另一个理由。

## 三 · ⭐⭐ 实测一：**它第一次跑就误报了，而且是在我测它的时候**

门刚装上，系统提示：

> ⛔ outward-guard：这是**对外 / 不可逆**的动作…`[git 推送]`

**它拦的是"测试门本身"的那条命令** —— 因为命令文本里**含 `git push` 这个字符串**
（用在 `printf` 里当样本），**并没有真的推**。

### 根因

**门匹配的是「命令文本」，不是「命令在做什么」。**
⇒ 任何**只是提到**该动作的命令都会中：
`echo "git push"` · `grep -rn "git push" docs/` · 写文档 · 写测试 · 写 PR 描述…

### 修法

**匹配「动作动词」之前，先去掉引号内的内容。**

```python
RE_QUOTED = re.compile(r"'[^']*'|\"[^\"]*\"|`[^`]*`")
verb_text = RE_QUOTED.sub(" ", raw)      # ← 用这个匹配动词
for t in rm_targets(raw):                # ← rm 的目标仍用**原文**
```

> ⛔ **`rm` 的目标必须用原文** —— 那里路径本身就在引号里（`rm -rf "my dir"`）。

**已加进自测**（`outward-guard` 19 项、`bulk-write-guard` 16 项）：
- `只是提到 · echo` → **放**
- `只是提到 · grep 文档` → **放**
- `只是提到 · 但动作是 commit` → **拦**

## 四 · ⭐⭐ 实测二：一个很容易骗过自己的**时序坑**

**`PreToolUse` 钩子在命令执行「之前」跑。**

⇒ 我那条命令**第一步就是 `cp` 覆盖钩子文件** ——
而**钩子判它的时候，装着的还是旧版本**。

**现象**：我刚"修完并重装"，紧接着的测试**又误报了一次** ——
看起来像"修复没生效"，**其实是那次判定用的是修复前的那份。**

### 教训

> **"装完立刻在同一个命令里测" = 测的是安装前的那份。**
> **重装和验证必须分成两条命令。**

（本仓的安装说明已据此写成两步；文中"复制 → 重启会话 → 再验"的顺序也是这个道理。）

## 五 · `path-guard` 的两处修正（用户提问逼出来的）

用户问：**「harness 里用的是样本吗？不能设置本机具体路径。」**

**扫下来基本干净**（无 `heweidong` / 无 `/Users/` / 无真实项目名），**但有一处不合格**：

```python
# 改前 —— 假设了"项目在 Desktop 下"
os.path.join(HOME, "Desktop", "<在此填你的项目根>")

# 改后 —— 纯占位符，不假设位置
os.path.realpath("<在此填你的项目根>")
```

**而且加了一道检查**：**占位符还在 ⇒ 拒绝工作**，并明说原因。

> ⛔ "白名单未配置 —— 这道门现在没有意义。
> **不改的后果**：它会把**所有**真实路径都拦下，或者你以为它在保护、其实什么都没拦。**而你不会知道。**"

**这与 `tools/check_public_hygiene.py` 的 `--no-private-list` 是**同一条规矩**：
### **「空」必须是说出来的，不能是默认发生的。**

**自测**：`path-guard` 10/10（新增反证：占位符在 ⇒ 判"未配置"；换掉 ⇒ 判"已配置"）。
