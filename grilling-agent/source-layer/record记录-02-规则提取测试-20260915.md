# 记录 02 · 规则提取测试（2026-09-15）

> **这是什么**：一次**诊断性测试**的原始结果。
> **测法**：把 `record记录-01-用户纠偏原文-20260915.md` 交给一个**空白上下文的子 agent**（它没参与过那次对话），
> 要求它「提取出让第三个 Agent 能照做的规则」，并**诚实报告提取不出的部分**。
> **目的**：验证「那几条纠偏够不够写成规则」——**推不出来的部分，就是源头缺的东西**。

## 一 · 能提取的规则（13 条，摘录体例）

> 体例：`规则(通用) / 反例(材料原文) / 正例(下次怎么做) / 机器可判定吗`

| ID | 规则一句话 | 机器可判定 |
|---|---|---|
| **R1** | 写操作前必须取得显式确认：本轮只发提议、不调用写工具 | 是 |
| **R2** | 进入下一步前，显式列出前置条件并等回答，不得自行判定已满足 | 是 |
| **R3** | 缺输入时主动**索取**（指名要什么），不得用"停止不动"代替推进 | 是 |
| **R4** | 提扫描/检索/反推类方案前，先复述推导方向并请确认 | 部分 |
| **R5** | 用户自身资产的事实（懂到哪层、谁做的决策）**只能问，不得推断** | 是 |
| **R6** | 用户声明的分层结构必须原样保留，不得合并、不得删层 | 部分 |

## 二 · ⚠️ 提取不出的（13 条 —— **这一节最重要**）

> 每条都是「材料里明明出了错，但**无法推出下次该怎么做**」。

| ID | 缺什么 | 一句话 |
|---|---|---|
| **G1** | **禁区清单** | 材料从未列出哪些是禁区、也没给识别方法 —— 第三个 Agent 连"界"在哪都不知道 |
| **G2** | **正例** ⭐ | 只有负例。用户把判据外置到"之前的对话记录"，而**该历史不在材料里** |
| **G3** | **重流程 vs 轻流程的触发条件** | 用户同时（a）否掉重流程、（b）说正因为轻流程失败才改用重流程。**区分条件一个字都没有** |
| **G4** | **"思考链"是什么形态** | 用户要"思考链"，但没给示例；也说不清是要更长推理、要提问、还是要展示不确定性 |
| **G5** | **"源头"的具体所指** ⭐ | 用户说"在源头按住"，但**没写源头指哪个文件、哪次确认、哪段 prompt** |
| **G6** | **阶段 1 / 阶段 2 的边界** | 阶段划分不在材料里，第三个 Agent 无法判断自己越界没有 |
| **G7** | **前置条件由谁定义、包含什么** | R2 能推出"要问"，但**推不出问什么**。问错清单 = 用户还得再纠一次 |
| **G8** | **"确认"的粒度** ⭐ | 一个要求停、一个要求动。是每个写操作一次？每阶段一次？每条消息都要？**推不出** |
| **G9** | **"两层融合"的产物形态** | "融合"与"不要混为一谈"字面有张力，且**没给出一条写好的项目条目作为样子** |
| **G10** | **归因规则** | 用户主动认责，但**材料没给区分"源头约束错"与"执行错"的判据** |
| **G11** | **用户看不出问题时，Agent 靠什么自证可靠** ⭐ | 用户"不合适会提出来"的前提是他看得出来 —— 但材料同时说他"不应该懂"。**整块空白** |
| **G12** | **21 与 29 哪个对、漏的 8 处是什么** | 材料没写差异原因，也没写最终采纳哪个数 |
| **G13** | **"纠偏 6 次"这个计数推不出任何动作** | 是计数不是判据 |

## 三 · 材料里互相矛盾 / 含糊的地方（8 条）

| ID | 矛盾点 |
|---|---|
| **C1** | **重流程该不该做** —— 同一段内自相矛盾（"不必要这么麻烦" vs "就是因此才改用 analysis"） |
| **C2** | **停 vs 动** —— 「做之前要确认，不要直接做」vs「为什么要停止不动」。至少三种解释，材料不足判定 |
| **C3** | **"反着扫"到底为什么被拒** —— 用户理由是"方向反了"，但他紧接着说「我该从 JD 结果**反推**执行过程」，这句本身也是反推。**关键缺口：他说过的"整体链路"原文没收录** |
| **C4** | **用户认责的意图** —— 真诚归因 / 安抚 / 给台阶？**Agent 该不该同时自查，材料没说** |
| **C5** | **"用户没直接纠"意味着什么** —— 没发现 / 发现了没提 / 认为无关紧要？三种情况结论完全不同 |
| **C6** | **两层边界** —— 「用 AI 生成/改进的代码」归哪层？举例的项目（`harness-engineering`）**恰好横跨两层** |
| **C7** | **R7 本身"听着对但没法执行到点"** —— 只禁止了一种形态，没许可另一种。**只能当必要条件，不能当合格线** |
| **C8** ⭐ | **"部分可判定"的规则保护力有限** —— 一个 Agent 完全可以**形式上每次都问"方向对吗"却每次都问错**，仍满足规则。**这是材料能支撑的上限** |

## 四 · 测试 agent 的判断（原话）

> **「够不够：部分够，但只够一半。」**
>
> 材料能支撑出一套**过程纪律规则**（R1–R3、R7–R10、R13，8 条机器可判定），
> 能挡住材料里记录的大部分纠偏（越权执行、误改文件、漏计数、模板化输出）。
>
> 但材料**完全支撑不出内容规则** —— 即"什么才是用户要的输出"。
> 原因是这份材料**通篇是负例**：每一条都在说"这样不对"，**没有任何一条给出用户认可的产出样本**。
>
> **最缺的，一句话：**
> ### 缺「被用户认可的正例」—— 一条他说"对，就是这样"的回复。
> ### 没有正例，就只能学会不做什么，学不会做什么。

## 五 · 我（主会话）从这次测试里加的两条读法

### 5.1 只从纠偏记录建约束，天花板很低

`C8` 那句是本轮最重的发现：**"不要做 X" 是可以被形式满足的。**

它和避坑库 `A5 · 验证的假象` 是**同一个病**：**测试全绿但没测到东西**。

⇒ **`grilling-agent` 若只靠纠偏记录建，会看着像纪律、实际拦不住。**

### 5.2 ⭐ 这次测试**本身生产了一个方法**

测法是：**把材料交给一个看不到上下文的读者，看它推得出什么、推不出什么。**
**推不出的部分 = 作者没说清的部分。**

**这和 Kappa 是同一个机制** ——
你的 JD 项目里，Kappa 用「两个独立编码者判得一样吗」暴露规则里的隐含假设；
这里用「一个空白读者推得出来吗」做同一件事。
**都是拿独立读者当镜子，照出原作者自己看不见的假设。**

⇒ 如果这条成立，"按住源头"就有了可执行形式：

> ### 把你写的东西给一个空白 agent 看。它推不出来的部分，就是你没说清的部分。
