## §2 · 关键原话（逐字）

### 2-1 · 目录为什么这么分

> 「这个文件夹中的 skills 不是用来加载的，它是 **skill 诞生和维护以及更新的文件夹**，
> 嵌套是因为 skill 要被加载，它的格式是 `skills/<技能名>/SKILL.md`，
> **如果直接写他没有来源层和维护层**，之后如果我要用，我会从
> `<仓>/<skill>/source-layer/<skill>/SKILL.md` 把最后这个 skill 层复制到需要的位置来使用和加载它。」

### 2-2 · ⭐⭐ 为什么这个 skill 重要（**本仓的原点**）

> 「**为什么 grilling-agent 重要。** 就拿刚刚进行的事来说，我让你创建那几个文件夹的目的，
> **你不明白，但是你按照我说的做了**，其他的 agent 会**不管我说什么，会跳过按自己认为的做，
> 然后改、没有了解意图直接做错**，同时**你还来追问我非常正确的**，
> 因为我们的对话上下文有这样的思维，**其他 agent 不会来问，导致后面的事情无限偏差**，
> **如果我发现还好，如果没有发现就是在一个错误的路上一直错。**
>
> **这个只是建文件夹这样简单的任务，我很容易查询和判断识别对错，
> 如果是几个 .py 文件呢，我基本上不可能去一个一个对和看，
> 这就是我做多重门禁和测试和 review 的目的**，和这个思维差不多是一样的。」

> ⇒ 这一段同时定了三件事：
> **① 正例长什么样**（「按他说的做」+「追问为什么」）
> **② 提问的必要性判据**（∝ 用户事后核验的难度）→ `record记录-03`
> **③ 为什么门禁和 skill 是同一件事的两面**

### 2-3 · ⭐ 受众是谁（**本仓首要原则**）

> 「`claude-agent-skills` 和 `<规则库仓>` **同样是给 Agent 看的，不是给人看的，这是最重要的原则**，
> **这个 skill 不是给我看的，是给其他 agent 看的。**
> 参考 pitfalls-kb 的 README 写法，还要里面的实例反例…等结构你看了吗，
> 三个 `record记录….md` 文件**应该放在 `source-layer` 下**才对吧，
> `Product/` 本机仓库名要同步修改。 1. 上全套样本，写好注意事项和要求。 2. **先做测试，再决定。**」

### 2-4 · 目录更正

> 「`record记录….md` 文件**我认为应该放在 `source-layer` 文件夹下面**，你放在 `<skill>/` 的理由是什么。」

### 2-5 · ⭐⭐ 门禁里不许有本机路径

> 「装用户级。同时 `grilling-agent` 中的 `harness` 文件夹中，**使用样本，不能设置本机具体路径**。是用的样本吗？」

> ⇒ 这一条后来直接变成了 `tools/check_public_hygiene.py` 的判据：
> **本机绝对路径一律报**；门禁脚本里只能写 `<占位符>`。

### 2-6 · 三源，与"只借鉴不写来源"

> 「第二件事：在用户级安装 `anthropics/skills/` 的 `skill-creator`。
> 第三件事：然后读本机已经安装的 `<他山之石>` skill 内容。
> 第四件事：等下我们要通过，`skill-creator` 和 `<他山之石>` 内容 + 我们自己内容，
> 去完成 `<本 skill>`，你先整理好记录在 `source-layer` 中，
> **`<他山之石>` 是 mattpocock 的，要内容规避，只借鉴，不要写来源，文档记录用中文。**」

> ⇒ 这就是 `record记录-07` 的来源，也是"**只借鉴结构、不复制文字、不署名**"这条约束的出处。

### 2-7 · 只装一个 skill

> 「`skill-creator` **只装这个 skill**，如果插件有绑定其他 skills，**不安装 plugin**，使用 npm 或者 git clone 安装」

### 2-8 · 开工前先确认

### 2-9 · ⭐⭐ 结构裁决（**A–G 七项**）

> **B** 先写。

> ⚠️ **C 是"为什么有 `references/` 层"的答案**：不是为了组织好看，

## §5 · 复现方法

```bash
# 从会话记录里抽用户发言（只抽文本块；工具结果/系统提醒/压缩摘要一律排除）
python3 <本仓>/grilling-agent/source-layer/grilling-agent/evals/dump-user-msgs.py \
    --session <会话.jsonl> --out <留档目录>
```

⚠️ **三个坑**（都踩过，脚本里已处理）：
1. **必须滤掉样板文字** —— 调 skill 时那条 `Base directory for this skill:` 有 3 万字，
   会被当成"用户发言"，把真发言淹掉。
2. **必须去重** —— 同一条消息会因重试/回显出现多次。
3. **必须分类** —— 一条会话里可能混着多个项目的对话，**直接整篇搬会把别的项目的私事搬进公开仓**。
