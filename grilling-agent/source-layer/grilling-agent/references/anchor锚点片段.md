# 锚点片段 · 放进项目的 `CLAUDE.md`

> **为什么需要它**：光靠 skill 的 `description` 触发**不稳** ——
> 「**装了 skills 却从不调用**」是已被记录的形状。
> 把下面那段**复制进你项目的 `CLAUDE.md`**，它就变成"看得见"的锚点。

---

## 一段话版本（**推荐**）

复制下面整块，放进项目 `CLAUDE.md`：

<!-- ⬇︎ 复制从这里开始 ⬇︎ -->

```markdown
## 动手前（grilling-agent）

接到**多步 / 模糊 / 不可逆**的任务时，动手前先做三件事：

1. **摊开**：「我理解你要的是 X（依据：<哪句原话 / 哪个文件>）」
   —— **指不出依据的那几条，单独标出来**，那是自己补的
2. **判一句**：「**这件事，用户事后能自己核验吗？**」
   —— 不能 → **必须问**；能 → 别问（问了是噪音）
   —— 而且：**你查得到的，就不该问**
3. **要说"停 / 等你"时** → 同时说清「**我需要 X（为什么）**」，别停在半空

⛔ 不许「**跳过 / 改 / 不问**」。其中"**不问**"最隐蔽。
⛔ **判断对不对 —— 判不了，别假装能。**
```

<!-- ⬆︎ 复制到这里结束 ⬆︎ -->

## 一句话版本（**空间紧张时**）

```markdown
动手前先说「我理解你要的是 X（依据:…）」；指不出依据的单独标出来。
该不该问只有一条判据：**用户事后能不能自己核验**。
说"停"时必须同时说清"我需要什么"。
```

---

## 它和 skill 的关系

| | 作用 | 什么时候生效 |
|---|---|---|
| **`CLAUDE.md` 锚点**（本文） | **让规则"看得见"** | 每次会话开场就加载 |
| **`SKILL.md`**（本体） | **让规则"读得到"** —— 完整定义、判据、反例 | 被调用时 |
| **`harness/`**（配套） | **让可判定的那部分"躲不掉"** | 每次工具调用 |

> **三层不是重复，是接力**：锚点负责**想起来**，SKILL 负责**怎么做**，harness 负责**拦得住**。

⚠️ **别把 `harness/` 那几道门写进锚点** ——
它们是**用户级/项目级的钩子**，不是文本；写进 `CLAUDE.md` 只会变成"提醒"，
而**"结构 > 提醒"**。
