## §2 · 为什么作废：**同一把坏尺子**

### 2.1 机制

`improve_description.py` 吃的是 `run_eval.py` 的结果。而 `run_eval.py` 的 docstring 写着：

```
Creates a command file in .claude/commands/ so it appears in Claude's available_skills list
```

```
project_commands_dir = Path(project_root) / ".claude" / "commands"
```

**它往 `.claude/commands/` 写 command 文件** —— 作者的假设是"command 会出现在 skill 列表里"。

**在这个版本上不会。** 这与 `run_loop` 是**同一处失效**（见 `record记录-08` §2.1）——
**就是同一个文件**。

> 本仓早已实测：同一份 skill、同一条 query，
> 装成 `.claude/skills/` 时 **3/3 触发**，而这个机制报 **0/3**。

### 2.2 数据自己喊出来了

| 轮 | train | test | 描述开头 |
|---|---|---|---|
| 1 | 6/12 | 4/8 | `Grill yourself before acting…`（原描述） |
| 2 | 6/12 | 4/8 | `Use this skill for work where you'd otherwis…` |
| 3 | 6/12 | 4/8 | `Use this skill before starting a task the us…` |
| 4 | 6/12 | 4/8 | `Use this skill when the user hands off a mes…` |
| 5 | 6/12 | 4/8 | `Use when the user hands off a messy, many-st…` |

**五条完全不同的描述，每一轮的 train / test 分数一分不差。**

> **一把尺子，喂什么进去都吐同一个数 —— 它量的不是那个东西。**

这条**不需要知道机制就能看出来**：**换了五次输入，输出恒定，那就是没在测输入。**
换句话说，**这批数据自己就带着"我无效"的证据，只是没人读它。**

## §3 · 因此，三件事

| # | 结论 |
|---|---|
| **1** | **`final_description` 不得采用。** 它是坏尺子的输出。采用了就是**拿一个已知失效的测量去改一个本来就没问题的描述** |
| **2** | **`best_description == original_description`** 这件事**也不能当支持**。它同样是这把尺子量的 —— **不是"原描述最好"，是"尺子分不出来"** |
| **3** | **4/8、6/12 这些数一个都不能引用** |

⇒ **原描述维持在 `SKILL.md` 里不动。** 这与 `record记录-08` §4 的裁决一致：
**当前证据不支持改描述。**

## §4 · 这是同一种失效的第三次

| # | 量具 | 症状 | 坏的方向 |
|---|---|---|---|
| 1 | `run_loop` | recall **0%**，五轮 | 让 skill **显得更差** |
| 2 | 自写脚本 v1 | recall **40%**，36 次超时 | 让 skill **显得更差** |
| 3 | **`run_eval` / `improve_description`** | **五轮分数恒定** | **看不出方向 —— 它根本不随输入变化** |

前两次是**朝一个方向偏**，这一次是**完全没读数**。
而第三次**更隐蔽**：前两次跑出来是"一个可疑的低分"，会让人起疑；
**这一次跑出来是"一套整齐的分数 + 一条像样的建议"，看起来像成果。**

> **本次最该记住的一条：**
> **不是所有坏掉的量具都会给出荒谬的数。**
> **有的会给出一个完全正常、完全整齐、无可挑剔的数表 —— 而它跟被测的东西毫无关系。**
>
> **唯一能识破它的，是问一句：「我改变输入，数变了吗？」**
> 这次变了五次输入，数一次没变。
