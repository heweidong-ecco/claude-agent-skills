## 四 · ⭐⭐ 一个 **「假通过」** —— 出现在我自己的测试里

写 `stop-guard` 时，我设计了一条「反证」：
> 把**豁免**拿掉 → 「停 + 说了缺什么」应该**反过来被拦**，以此证明豁免真的在起作用。

**它"通过"了。但它什么都没测到。**

因为那条反证文本是 `"我先停在这里。要继续，我需要你补充…"` ——
**而我的触发词里有 `先停一下`、没有 `先停`** ⇒ **触发词压根没命中** ⇒
"拿掉豁免后仍不命中" 是**必然的**，与豁免无关。

**修法**：在反证前加一行**断言**，先证明样本**真的命中触发词**：

```python
assert RULES[0][1].search(probe), "反证样本没命中触发词 —— 这个反证是假的"
```

> **教训**：**"反证通过" 也可能什么都没证明。**
> 反证必须**先证明它能被证伪** —— 否则它只是另一条永远绿的测试。

## 五 · ⛔ 决定性实测：`stop-guard` 被否定

**测法**：拿一个真实会话里 **241 条** assistant 回答，逐条跑 `find_hits`。

**结果**：

| 项 | 值 |
|---|---|
| 命中 | **9 条（3.7%）** |
| **真阳** | **0 条** |
| **误报** | **9 条（100%）** |

**逐条看触发源：**

| 条 | 触发词 | 上下文 |
|---|---|---|
| 77 | `先停` | 「出来**先停**下给你过目，行吗？」← 在征求同意 |
| 87 / 88 | `等你` | 「停在这里，5 个问题**等你**」+ 列了 5 个问题 ← **说了要什么** |
| 95 | `等你` | 「还是**等你**确认了我再动」 |
| 130 | `等你` | 「**等你**点头，我就做这 3 步」 |
| 150 / 161 / 205 | `等你` | 「**等你**往里加内容」「**等你**放东西」「`SKILL.md` **等你**写」 |
| 239 | `先停` | **在讨论这道门时，引用的一句坏回答** |

**根因**：

> **触发词抓的是「停」这个动作，不是「没说缺什么」。**
> 而实践中说"停 / 等你"时，**几乎总是同时说了要什么** ——
> **豁免是常态，不是例外。**

**收窄可行吗？** 不行：
- 豁免词表**永远列不全**（等你确认 / 点头 / 决定 / 回 / 放 / 写 …）
- 而机器**判不了"具体"**

**241 条里，「停但不说缺什么」这个形状一次都没出现。**

### 5.1 ⇒ 结论（**比这道门本身有用**）

> `stop-guard` 是能找到的、**最接近「意图」的代理指标** ——
> **它在真实语料上 100% 误报。**
>
> **⇒「意图层」可能连它的代理都拦不住。**

**这与早就写下的那条判断一致**：

> 「很多可以通过 harness / setting JSON / rules 拦截，**唯有意图很难拦截**。」

**这次实测把它从"判断"变成了"有数据的结论"。**

**处置**：**不注册进 settings**（见 §一 的 ⛔）。文件保留，**留作有证据的"行不通"记录**。
**意图那一层，交给 `SKILL.md`（L1/L2）。**
