# griling-agent · harness（拦截模版）

> **一句话结论**：**意图拦不住；但「意图没被摊开」拦得住。**
> 这份模版装的是**除意图之外**、能机器判定的那几层。
>
> **读者是 Agent。人是维护者，不是读者。**
> 由此：**写动作，不写感想**；**能被扫读**；**不要求读者去本目录之外翻东西**。

---

## 0 · 装之前必须先知道四件事

> 不读这四节，装了等于没装 —— **而且会更糟：你会以为装了。**

### ⚠️ ① 复制文件 ≠ 装上了

`settings.json` **只从 cwd 的 `.claude/` 加载，无父目录回退。**

⇒ 两条路，选一条：

| 装到哪 | hook 脚本放哪 | command 怎么写 |
|---|---|---|
| **项目级** `<项目>/.claude/settings.json` | `<项目>/.claude/hooks/` | `python3 "$CLAUDE_PROJECT_DIR/.claude/hooks/<名>.py"` |
| **用户级** `~/.claude/settings.json` | `~/.claude/hooks/` | `python3 "$HOME/.claude/hooks/<名>.py"` |

**要覆盖"别的项目里的 Agent"，只能用用户级** —— 项目级的在别的 cwd 下永远不会被读。

### ⚠️② 子 Agent 会被 `ask` 挂死

`permissionDecision: "ask"` 时**主会话会弹确认给人**；
但**子 Agent 无人可批准** ⇒ **它会一直挂着**（同类项目已有实证）。

⇒ **本模版所有钩子都做「故意不对称」**：

| 谁在跑 | 怎么判 | 行为 |
|---|---|---|
| **主会话** | hook 输入里 **没有** `agent_type` | `permissionDecision: "ask"` |
| **子 Agent** | hook 输入里有 `agent_type` | **只输出 `additionalContext`，不 ask** |

⛔ **写新钩子时别漏这一条。** 漏了 = 把子 Agent 挂死。

### ⚠️③ 门禁会自己腐烂

门上线后**没人再盲测它**，它就会静默失效 —— 同类项目实测抓到过 **2 个 100% 触发率的缺陷**。

⇒ **每道门必须自带 `--self-test`**，且：
- 测**违规样本 → 是否变红**
- 测**合规样本 → 是否误报**
- 测**反证**（把判据拿掉 → 是否真的不再命中）

**跑法**：`python3 <钩子>.py --self-test`

### ⚠️④ 钩子是「防手滑」，不是「防对抗」

它拦的是**没走脑子**，不是**刻意绕**。已知绕过方式：

命令替换 `$(...)` · 变量拼接 · 编码解码 · 重定向的间接写入 · **任何不经过工具的访问**（某脚本内部自己去读写）。

**别把它当安全边界。**

### ⚠️⑤ 装哪一层 —— 判据：**这道门的知识是「通用」还是「项目特定」**

| 知识性质 | 装哪层 | 例 |
|---|---|---|
| **通用** —— 任何项目都成立 | **用户级** `~/.claude/settings.json` | ① 对外动作要授权 · ② 批量改要先看清单 |
| **项目特定** —— 每个项目不一样 | **项目级** `<项目>/.claude/settings.json` | ③ 哪些目录算"内"（白名单） |

**为什么项目特定的不能装用户级**：白名单只能填一个**宽**范围（否则误拦）——
**填宽了等于没拦，而你会以为它在保护。**

> ⚠️ **另一条层级坑**：`.claude/settings.json` **无父目录回退**（从子目录启动就不加载）；
> 但 `.claude/settings.local.json` **相反，它从 git 仓库根读**。两个文件行为不同，别记混。
> 而 `CLAUDE.md` **会向上遍历** —— 同项目里它找得到、`settings.json` 找不到。

### ⚠️⑥ `PreToolUse` 在命令执行**之前**跑 —— "装完立刻测"会测到旧的

若你在**同一条命令**里既 `cp` 覆盖钩子、又跑测试 ⇒
**钩子判它的时候，装着的还是旧版本。**
现象是"修复没生效"，实际是**时序列**。

> ⛔ **重装与验证必须分成两条命令。**
> （同理：`settings.json` 是会话启动时读的 —— 改完要重启。）

### ⚠️⑦ 门匹配的是「命令文本」，不是「命令在做什么」

⇒ **只是提到**某个动作的命令也会中：`echo "git push"` · `grep -rn "git push" docs/` · 写文档 · 写测试。

**已处理**：匹配「动作动词」前**先去掉引号内内容**（见各钩子的 `RE_QUOTED`）。
⚠️ 但 **`rm` 的目标提取仍用原文** —— 那里路径本身就在引号里。

## 1 · 三道门（各自拦什么 / **不拦什么**）

| # | 钩子 | 挂在 | 拦什么 | **不拦什么** |
|---|---|---|---|---|
| **①** | `outward-guard.py` | `Bash` | `git commit` / `git push` / `gh repo create` / `gh pr merge` / `gh release` / **不可逆删除** | 读操作、本地查询 |
| **②** | `bulk-write-guard.py` | `Bash` | **批量改写命令**：`find … -exec … -i` / `for … sed -i` / 一次 `rm` 多个 | 单文件编辑（那是 `Edit` 工具，不走这） |
| **③** | `path-guard.py` | `Bash` `Read` `Write` `Edit` `NotebookEdit` `Glob` `Grep` | **白名单之外的本地路径** | **GitHub / 网络**（无本地路径）；白名单内 |

**③ 的白名单**是**每项目配**的，写在钩子顶部 `ALLOW_ROOTS`。**装之前先改它。**

### ⛔ 1.1 第四道门存在，但**不要注册它**

`hooks/stop-guard.py`（试图拦「说了停但没说缺什么」）**已实测否定**：

> 在 **241 条**真实回答上跑 → 命中 **9 条**，**9 条全是误报、真阳 0 条**。
> 触发源几乎全是 `等你`（「等你确认」「等你点头」）—— **那是"把球踢回去"，正是想鼓励的行为**。
> 241 条里，「停但不说缺什么」这个形状**一次都没出现**。

**根因**：触发词抓的是「停」这个动作，**不是「没说缺什么」**。
而实践中说"停/等你"时**几乎总是同时说了要什么** —— 豁免是常态，不是例外。

**⇒ 意图那一层，交给 `SKILL.md`，不要指望 hook。**
**本文件保留它，是为了留下这条有证据的「行不通」记录。**

## 2 · 装法

```bash
# 假设要把三门装到「用户级」
mkdir -p ~/.claude/hooks
cp hooks/*.py ~/.claude/hooks/

# 把 settings.user.json 的内容合并进 ~/.claude/settings.json
#   （**合并**，不是覆盖 —— 那里面可能已经有别的钩子）
```

**改白名单**（③ 必做）：编辑 `~/.claude/hooks/path-guard.py` 顶部的 `ALLOW_ROOTS`。

**验证装上了**（三步，都要过）：

```bash
python3 ~/.claude/hooks/path-guard.py --self-test
python3 ~/.claude/hooks/outward-guard.py --self-test
python3 ~/.claude/hooks/bulk-write-guard.py --self-test
```

**⚠️ 第三步过了也不算装上** —— `settings.json` 是**会话启动时**读的。
**必须重启会话**，然后做一次真实触发测试（见 §3）。

## 3 · 真实触发测试（**这一步不许跳**）

```bash
# ③ 路径门：应弹确认（或子 Agent 下应注入提示）
cd /srv                # 白名单外（换成你自己白名单之外的目录）
ls

# ① 对外门：应弹确认
git commit --allow-empty -m "test"

# ② 批量门：应弹确认
find . -name '*.md' -exec sed -i '' 's/x/y/' {} \;
```

**若没弹** ⇒ 门没接电。回到 §0① 重看 `settings.json` 的位置。

## 4 · 三道门**加起来**也拦不住什么（**别误以为安全**）

| 拦不住的 | 为什么 |
|---|---|
| **意图理解错** | 不可判定 —— 这是本 skill 的主战场，**不是 harness 的** |
| **方案选得不对** | 同上 |
| **"我以为你要 X"** 里的 X 对不对 | 同上 |
| 结论有没有依据 | **试过了**：`stop-guard.py` —— **实测 100% 误报**（见 §1.1） |
| 子 Agent 内部的行为 | hook 挂在工具上；Agent 不可控的推理过程挂不上 |

> ⛔ **本模版是「除意图之外的拦截」。意图那一层，靠 `SKILL.md`，不靠这里。**
