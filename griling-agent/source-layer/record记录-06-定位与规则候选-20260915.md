## 一 · 定位（一句话）

> **让 Agent 在「动手前」把「我以为你要什么」摊开；在「你事后核不了」的地方提问；不碰没让动的东西。**

---

## 二 · 它靠什么起作用（**这决定规则只能写成动作**）

依据：`record记录-04` §5 的实测 ——

> **意图层拦不住**。连它的代理指标（`stop-guard`）都在 **241 条**真实语料上
> **100% 误报、真阳 0**。

**⇒ 这个 skill 只能要求「动作」，不能要求「判断」。**

| 废的要求（不可判定） | 换成（可执行） |
|---|---|
| "你要更懂用户" | 「开工前写出一句『我理解你要 X，依据是 Y』」 |
| "你要谨慎" | 「说停的时候，同时说清缺什么」 |
| "别自作主张" | 「不许动用户没让动的东西」 |

**核心机制**（`record记录-04` §5.2）：

> **推不出来的部分 = 没说清的部分。**
> —— 拿一个「**看不到上下文的读者**」当镜子。

**这与 Kappa 是同一个机制**：Kappa 用「两个独立编码者判得一样吗」暴露隐含假设；
这里用「一个空白读者推得出来吗」做同一件事。

## 三 · 规则候选（6 条）· **待裁决，未写入**

| # | 规则 | 依据 |
|---|---|---|
| **R1** | **开工前摊开**「我以为你要的是 X（依据：<哪句 / 哪个文件>）」，并**标出指不出依据的那几条** —— 那些是你自己补的 | `record记录-04` §5.2 |
| **R2** | **只在「用户事后核不了」的地方才必须问**。判定句：**「这件事，他事后能自己核验吗？」** 能就别问（问了是噪音）；不能就必须问 | **`record记录-03` §二** |
| **R3** | **说「停 / 等你」时，必须同时说清缺什么** —— 「要继续，我需要 X（为什么），拿到后我做 Y」 | `record记录-03` §四 · `record记录-04` §5 |
| **R4** | **不许「跳过 / 改 / 不问」** —— 三个动作逐级加重：不执行用户明说的 → 动没让动的 → 全程没一处暴露"我不确定" | `record记录-03` §四 |
| **R5** | **独立读者测试** —— 要交给别人执行的东西，先给一个看不到上下文的读者看；**他推不出来的部分就是你没说清的** | `record记录-04` §5.2 |
| **R6** | **反复出错 → 指向源头，不继续改产物** —— 同一问题被纠 ≥2 次，停下指出「哪条初始约束缺失」 | `record记录-01` §8 |

**这条本身就解释了「为什么它在 SKILL.md 而不在 harness/」。**
