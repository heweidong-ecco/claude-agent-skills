# claude-agent-skills

> **Claude Code / AI Agent 的 Skill 开发与维护仓库** —— 从需求记录到可加载的 `SKILL.md`。
>
> **本仓不是"拿来即用"的分发库**，而是 skills 的**诞生、维护、更新**的地方。

---

## 一 · 目录约定

```
<skill-name>/
  source-layer/                  ← 来源层与维护层（**过程**）
    record记录-*.md              ← 原始材料：需求、纠偏、测试、决策
    <skill-name>/                ← 成品层（**只有这一层是拿去加载的**）
      SKILL.md                   ← 大写，标准文件名
```

**为什么要两层：**

| 层 | 作用 |
|---|---|
| `source-layer/` | 记录这个 skill **怎么来的** —— 依据、迭代、验证。**持续更新。** |
| `<skill-name>/` | **脱敏后的成品**。要用时，**把这一层复制出去**即可加载 |

> **取用**：
> ```bash
> cp -r <skill-name>/source-layer/<skill-name>/ ~/.claude/skills/
> ```

---

## 二 · ⛔ 占位符规范（**硬性**）

**本仓是 public ⇒ 私有项一律用 `<…>` 占位符。**

| 禁止出现 | 换成 |
|---|---|
| 私有仓库名 | `<私有仓>` `/<私有 kit 仓>` |
| 内部目录名 | `<内部工作目录>` |
| 用户绝对路径（`/Users/…`） | 相对路径，或 `<项目根>/…` |
| 家目录路径（`~/…`） | 同上 |
| 邮箱 / 密钥 / 手机号 | **一律不写** |

> **逐字引用中若必须替换**：在该文件**头部加「脱敏声明」**，写明
> 「除占位符外一字未改」—— **不许静默改动引文**。

## 三 · 四层门禁

| 层 | 文件 | 作用 |
|---|---|---|
| **唯一真相** | `tools/check_public_hygiene.py` | **CI 与本地跑的是同一份**（唯一校验真相） |
| **本地左移门** | `.githooks/pre-commit` | 提交前拦 |
| **终门** | `.github/workflows/hygiene-check.yml` | push / PR 必跑 |
| **防腐** | `check_public_hygiene.py --self-test` | **突变验证**：证明违规时**真的会变红** |

**装本地门**（⚠️ **每台机器装一次，不随克隆携带**）：

```bash
git config core.hooksPath .githooks
```

**绕过**：`git commit --no-verify` —— 请说明为何绕过。

## 四 · ⚠️ 已知局限（**不假装全绿**）

`tools/private-names.txt`（私有名清单）**只在本地存在、不进仓库**
（已被 `.gitignore` 排除）。

**因此：**

| 检查项 | 本地 pre-commit | CI |
|---|---|---|
| 绝对路径 / 家目录路径 | ✅ | ✅ |
| 邮箱 / 密钥样式 / 手机号 | ✅ | ✅ |
| **私有仓名 / 内部目录名** | ✅ | ❌ **拦不了** |

**这是有意的取舍** —— 把私有名写进检查器，等于**检查器自己泄露**。

### 4.1 ⛔ 但"空"必须是**说出来的**，不能是**默认发生的**

**清单缺失时静默跳过，正是本项目点名要防的形状：**
> 该有输入的地方没有输入，系统不报错、用默认值继续，**产出看起来完全正常**。

所以脚本的行为是：

| 场景 | 行为 |
|---|---|
| 清单存在 | 跑 6 项 |
| **清单缺失，且没传开关** | **直接报错退出**（默认） |
| 清单缺失，**显式传 `--no-private-list`** | 跳过第 6 项，并**打印"这是声明的缺口，不是通过"** |

**CI 传这个开关**（因为清单必然不在仓库里）；
**本地不要传** —— 本地应当把清单建出来。

## 五 · 🔁 换机器（`git clone` 之后必须做的两件事）

**这两样东西不会随 clone 过来，而且它们会「看起来装好了」：**

| 项 | 会 clone 吗 | 为什么 | 不做的后果 |
|---|---|---|---|
| `core.hooksPath .githooks` | ❌ **不会** | 它是**本地 git 配置**（存在 `.git/config`），clone 是新建 `.git` | **门不生效** —— 但 `.githooks/pre-commit` **文件在**，看起来像装好了 |
| `tools/private-names.txt` | ❌ **不会** | 被 `.gitignore` 排除 | 本地门会**报错**（不再静默跳过，见 §4.1） |

**clone 之后依次跑：**

```bash
git config core.hooksPath .githooks          # ① 装本地门
$EDITOR tools/private-names.txt              # ② 重建私有名清单（每行一个名字）
python3 tools/check_public_hygiene.py        # ③ 验证两道都活了
```

> ⚠️ **第 ① 步的坑**：文件在、门没接电 —— **这是"结构在、但静默失效"**。
> 同上，**CI 是拦不住这个的**（它只管仓库里有什么，不管你这台机器配了什么）。

## 六 · 为什么要有这个仓库

skill 的内容来自**真实协作过程**：需求、被纠正的记录、测试结果、决策。
**这些过程本身就是质量证据** —— 它们解释了「这条规则凭什么成立」。

把它们和成品放在一起，是为了让**后来读的人（或 Agent）能判断这条规则可不可信**。
